# 铁路参数化视觉验收体系

对 go-topo 铁路专业 (轨道/道岔/接触网) 参数化定义与生成的验收管线:
以**真实名义参数** (GB 2585 钢轨、TB 10001 线路、TB 10009 电力牵引供电) 逐项生成,
经四道闸门判定与真实情况的符合性, 并产出可目检的三维图库。

**最新结果: 68 项 = 66 通过 + 2 已知偏差 + 0 失败** (全量 ~140s)。

站场组装 2026-10 二轮强化: 道岔岔枕跟随侧股加长、菱形交叉实测角 (支持直角)、
交叉区岔枕、导曲线半径实测拟合、曲线主向不出岔守卫 — 详见 AGENTS.md
「GeoJSON 轨道输入」与本文 用例分组 TRACK-ASM 新增 3 项 (锐角/直角菱形交叉、
货场直角交叉站场)。

## 运行

```sh
# 1. 生成验收产物 (manifest / report / STL 图库)
ACCEPTANCE_DIR=./acceptance CC=/usr/bin/clang CXX=/usr/bin/clang++ \
  go test -run TestGenerateRailwayAcceptance -v -timeout 40m .

# 2. 本地查看 (视觉目检)
python3 -m http.server 8318 --directory acceptance
# 打开 http://127.0.0.1:8318           — 12 项/页网格 (判定徽章+实测尺寸)
#      http://127.0.0.1:8318/?i=14    — 单件四视图 (轴测/正视/俯视/侧视) + 逐项检查表
#      http://127.0.0.1:8318/?shot=1&page=0 — 截图模式 (渲染完成置 document.title=READY)

# 3. 验收报告
open acceptance/report.md
```

`ACCEPTANCE_DIR` 未设置时测试 skip, 常规 `go test ./...` 不受影响。

## 四道闸门

| 闸门 | 内容 | 说明 |
|------|------|------|
| 1. 生成有效性 | shape 非 null; 小装配跑 `IsValid()`; 大装配 (复合体 ≥ 百实体) 跳过 BRepCheck (十分钟级代价且持锁阻塞其它 cgo), 以尺寸闸门+视觉目检替代 | heavyCases 表 |
| 2. 尺寸符合性 | **三角化后**取 bbox 各轴 vs 真实工程值区间 (accExpect 表); 先三角化是因为未三角化的 Bnd_Box 按曲线/曲面极点估算, 对 Bezier 索类高估可达 ~1.2× | 单位 mm |
| 3. 参数化闭环 | 锚段/站场布局 `ToJSON→FromJSON→FromLayout` 再生成, 元素数与 bbox 逐位一致 | PARAM 组 |
| 4. 视觉符合性 | three.js 四视图目检 (`acceptance/index.html`), 人工/评审确认形态与真实设备一致 | 网格页+单件页 |

未通过且非已知偏差 → **失败**; 与真实标准存在建模层级差异的项标记 **已知偏差**
(`knownDevCases`), 单列于报告, 不计为验收失败。

## 验收发现与处置记录 (2026-10 首轮)

### 已修复的真缺陷 (C++ / Go 代码, 均已回归验证)

1. **钢轨与轨枕同层互穿** — `create_straight_track` / `create_curve_track` /
   `create_turnout` / `CreateTrackFromCenterline` 中钢轨底面在中心线平面 (z=0),
   与轨枕 (z 0..枕高) 互穿; 真实轨道轨底应落在枕顶。
   修复: 轨底统一抬升至枕顶 (直线 z=枕高; 道岔 z=200 + 辙叉随轨面平移;
   GeoJSON/站场路径在 Go 侧 `raiseCenterlineToRailTop` 抬升)。
   验收证据: 直线正线总高 656mm = 道床300 + 轨枕180 + 钢轨176。
2. **曲线超高只作用于道床** — 超高 120mm 时道床倾转而轨枕/钢轨保持水平。
   修复: 钢轨按外轨 +se/2、内轨 −se/2 抬降 (与道床绕中心线倾转 atan(se/gauge)
   的轨面高差一致), 轨枕随道床顶面绕切向同步倾转。
3. **扣件忽略轨距** — `create_fastener` 丢弃 Gauge/Spacing, 只生成单轨一套。
   修复: 按轨距生成两轨各一套 (`create_fastener_pair`, ±gauge/2)。
4. **接触线零值可选参数直接失败** — `create_contact_wire` 对 `bottomRadius<=0`
   抛异常, 而下方本有 R*0.6 默认值逻辑; 移除过严守卫。
5. **线索弛度只有参数的一半** — 接触线/承力索/悬索缆 (含 centerline 采样) 用
   三点 Bezier 拟合抛物线时控制点偏移 = sag, 实际垂度只有 sag/2 (Bezier 中点
   性质), 与吊弦/锚段布局的全弛度抛物线假设不一致。修复: 控制点偏移 2×sag,
   曲线中点真实垂度 = sag。验收证据: 50m 跨接触线 dz=521 (500 弛度+12.9 径)。
6. **悬索硬横跨吊弦零直径崩溃** — `dropperCableDiameter=0` 时
   `create_suspension_cable` 抛异常, C API 静默吞掉 → 整体返回 null。
   修复: 缺省按 cableDiameter×0.4 兜底。

### 验收体系自身修正 (非库缺陷)

- 生成器 GeoJSON 用例坐标误写为 `i*1000` 米 (=60km 轨道) — 曾是"生成卡死"的
  主要放大器; 改为 i 米。
- `TrackGeoProperties.BallastTopWidth` 注释"默认 3600"与实现不符
  (缺省 0=不生成道床) — 修正注释, 验收用例显式传 3600。
- 直埋基础的 Length 是圆柱坑直径取 min(长,宽) — 按实现语义修闸门。
- 测试数据单位陷阱 (2026-10 二轮再次踩到): GeoJSON 坐标按米书写, 写成毫米值
  会被 coordScale 再放大 1000 倍 — 弧长行走/偏差守卫全部失效且无报错, 表现为
  "守卫阈值永远不触发"。曲线站场用例必须以米为单位构造坐标。

### 已知偏差 (报告单列, 不计失败)

- ~~道岔全长较专线标准偏长 ~20%~~ — **已修复 (2026-10 二轮第三批)**: 超长主因是
  岔前段取 `−swLen−2000` (把尖轨全长错当地岔前段, 虚增 ~7m), 次因 12号表值
  R350k (提速值) 与辙叉长系数。修正为 岔前 2.6m + 普通型 R330k + 辙叉 4.5m,
  并配合导曲线坪心收直: 9号全长 29.2m (标准 29.57, −2.3%)、12号 37.9m
  (标准 36.82, +2.9%), 两个道岔用例已退出 knownDev 转正常闸门。

## 站场组装强化 (2026-10 二轮)

首套 65 项验收跑通后, 针对「车站/编组站/货场」站场组装策略的两批修复
(回归: track_yard_test.go 新增 5 测试 + 验收 TRACK-ASM 新增 3 用例;
第二批由 4 张实物/布置图/3D 渲染参考图对照触发):

第一批 (布局识别与布岔):

1. **站场道岔无岔枕** — 站场路径 `TurnoutParams` 未传间距, C 侧
   count/spacing 双零 → 岔区一根岔枕都不生成 (验收用例单独传 600 掩盖)。
   修复: C 侧缺省 600 兜底 + 站场路径显式传股道属性。
2. **岔枕不跟随侧股** — 原来岔枕长 2500→2700 线性渐变, 12 号岔尾侧股已偏出
   2.6m 而枕长不足。修复: 每根岔枕按侧股两轨 (Ro/Ri 圆) 实际位置定长
   (2500→5200) 并向侧股侧平移, 承轨槽四轨位对位。
3. **直角菱形交叉辙叉角失真** — 交叉角 snap 到就近号数 (90°→9号), 辙叉按
   atan(1/9) 浅角生成, 与实际 90° 交叉完全错位。修复: `frog_params.frogAngle`
   显式实测角 (>0 生效, 0 保持旧行为)。
4. **交叉区无岔枕 + 辙叉低于轨面 200mm** — 交叉单元岔枕 + 放置 z 抬升到轨面。
5. **导曲线半径用查表值** — 侧线实际半径与号数表值不符时岔后折角。
   修复: 实测辙叉角 + 半径拟合 (直侧线 4hg/tan²α / 曲侧线 arc/α)。
6. **曲线主线无守卫** — 道岔区内弯直偏差 >100mm 不出岔, 记入 `YardLayout.Warnings`。

第二批 (对照参考图的结构性重做):

7. **菱形交叉塌缩成单点** — 原 `create_frog` 把交叉做成一个点上汇聚的 4 根
   尖轨; 实物 (参考图1) 是**有限长度编织区**: 两线各两轨在 4 处交叉, 长对角端
   2 处锐角辙叉 (V尖+翼轨+护轨) + 短对角端 2 处钝角交叉 (断轨+轮缘槽), 沿线路
   展开 2hg·cot(α/2) (1/12 约 43m)。重做为 `create_diamond`, 站场路径交叉改用
   真菱形 + 股道让位分段 (交叉区钢轨由单元提供, 消除四层轨重叠)。
8. **导曲线过岔心继续弯** — 布置图 (参考图3/4) 中导曲线轨止于辙叉, 岔后顺
   辙叉角直段引出; 原圆弧穿岔心继续弯与直的辙叉尖轨冲突。修复: 导曲线在
   辙叉心切点收直, 岔后直段 (同时改善直侧线岔后衔接)。

第三批 (全长对标, 消除 knownDev):

9. **道岔全长超长 ~20%** — 反推标准尺寸 (专线4193/4128 的 L/a/b + 辙叉几何
   自洽) 定位三处: ① 岔前段取 `−swLen−2000` (9.7m@12号), 实际岔前只有基本轨
   前伸 ~2.6m — 主因; ② 12号表值 R350k 为提速道岔值, 普通固定型为 R330k;
   ③ 12号辙叉长 0.28·gauge·N=4.82m, 实际 ~4.5m。修正后 9号 29.2m (−2.3%)、
   12号 37.9m (+2.9%), 两用例转正常闸门, knownDev 清零。

### 环境约束

- **大装配 BRepCheck 代价过高**: 450 实体的锚段/正线复合体 `BRepCheck_Analyzer`
  耗时十分钟级, 且验证期间持锁阻塞其它 cgo 调用 — 大装配用例跳过 IsValid。
- **长线性受限**: 数万轨枕级长正线在内存饱和机器上性能急剧退化; 验收用例
  正线取 60m。批量长线生成建议走装配分片。
- 生成器每用例后强制 `runtime.GC()+FreeOSMemory()`, 避免 cgo 大形状滞留叠加 OOM。
