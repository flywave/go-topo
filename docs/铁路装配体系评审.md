# 铁路装配体系评审 (组装策略优化)

围绕"前端不在全局地图中编辑金具/零件级对象"的目标, 按铁路工程专业层级
将元件逐级组装为接触网与铁轨网络。本文记录 评估 → 优化 → 验证 → 评审 全过程。

## 一、铁路专业层级依据

真实铁路工程的功能分解 (TB 10009 电力牵引供电 / TB 10001 线路):

```
接触网系统 (OCS)
└── 锚段 (tension length,两端补偿、逐段张紧)         ← 地图级对象
    ├── 支柱装置 (support: 支柱+腕臂+定位[+补偿])    ← 编辑级对象
    └── 跨距 (span: 两支柱间的悬挂)                  ← 编辑级对象
        ├── 接触线 / 承力索 (跨内线索)
        └── 吊弦群 (间距 5~10m, 长度由两索弛度差定)   ← 零件, 仅展开可见

轨道网络 (站场/区间)
├── 股道 (track)                                    ← 编辑级对象
│   └── 轨道结构区段 {钢轨组 + 轨枕 + 道床}          ← 零件级批对象
├── 道岔 (turnout)                                  ← 功能单元, 独立对象
└── 菱形交叉 (crossing)                             ← 功能单元, 独立对象
```

**编辑粒度原则**: 全局地图只呈现 功能单元 粒度 (锚段→支柱/跨距, 站场→股道/道岔);
细部调整在单元内展开 (跨距内改弛度/吊弦表, 股道内改裁剪/轨枕参数);
零件级 (单根吊弦、单个垫板) 不进入地图编辑器的对象列表 —— 与设计院
"先布锚段quadro、再调跨距、最后出零件表" 的工作流一致。

## 二、评估 (优化前现状)

| 维度 | 优化前 | 问题 |
|------|--------|------|
| 锚段结构 | 46 个元素全平铺 (mast_i / cw_i / mw_i / dropper_{i}_{k}) | 地图对象爆炸; 线索/吊弦与支柱混层; 无"跨距"概念 |
| 站场结构 | 7 元素平铺 (rails_i / sleepers_i / turnout_i) | 股道无分组; 部件级与功能单元级混层; 根节点名是首个部件名 |
| 重建粒度 | 仅叶片级 builder | 无法按跨距/股道粒度整棵重建, 编辑弛度需逐件改 |
| 寻址 | `Get` 仅顶层 | 嵌套元素不可寻址, 前端无法按路径定位 |
| 容器占位 | 根容器 vertex 在原点 | 污染全局 bbox (裁剪 50m 后 bbox 几乎不缩) |

## 三、优化 (已实现)

### 3.1 层级重组

```
anchor_section (锚段, 57 项验收中的锚段案例 250m/5跨)
├── mast_0..5    支柱装置 (ocs_mast 配方, Location 放置, 可整柱移设)
└── span_0..4    跨距子装配 (ocs_span 装配级配方)
    ├── cw_i / mw_i      接触线/承力索 (叶片配方, 名字保持历史约定)
    └── dropper_i_k      吊弦 (叶片配方)

yard (站场)
├── track_0..n   股道子装配 (yard_track 装配级配方: 原始中心线+裁剪+参数)
│   ├── rails_i / sleepers_i   轨道结构叶片 (叶片配方)
├── turnout_i    道岔 (yard_turnout 配方)
└── crossing_i   菱形交叉 (yard_crossing 配方)
```

顶层对象数: 锚段 46 → **11** (根+6柱+5跨), 站场 7 → **5** (根+3股道+1道岔)。

### 3.2 装配级参数化机制 (assembly_parametric.go)

- 新增 `RegisterAssemblyBuilder(type, fn)`: builder 由配方 JSON **整棵重建子装配**
  (区别于叶片级 builder 只回单 shape); `RebuildFromParametric` 优先走装配级 builder,
  导出的 children 作为前端编辑面, 不参与重建 (子零件由配方确定性再生)。
- 新增 `Assembly.Get` 三级寻址: 顶层短名 → 路径 (`span_0/cw_0`) → 全树唯一深度名。
- `AddAssembly` 已有的配方树同步机制天然支持嵌套导出, 无需 C++ 改动。

### 3.3 跨距/股道配方 (前端编辑面)

- `ocs_span`: {接触线[径/弛度/端点], 承力索[同], 吊弦 T 表} —— 改弛度或吊弦表,
  单跨整棵重建 (吊弦长度按两索弛度差自动重算)。
- `yard_track`: {原始中心线, TrimS/TrimE, 轨道参数} —— 改裁剪或轨枕参数, 整股重建。

### 3.4 附带修复

- 根容器/子装配占位 vertex 移入自身几何范围 (原在原点, 污染 ToCompound bbox ——
  站场裁剪 50m 后全局 bbox 只缩 130mm 的根因)。

## 四·五、支柱角色与锚段关节覆盖 (2026-10 追加)

按支柱在接触网中的功能角色补全组装覆盖 (TB 10009 支柱设置):

| 角色 | 组装形态 | 出现位置 |
|------|----------|----------|
| 中间柱 (非锚柱) | 柱体+单腕臂复合体 | 锚段中间柱 (批量) |
| 锚柱 | 柱体+单腕臂+**补偿装置+坠砣+拉线** | 锚段端柱 (两端) |
| 转换柱 | 柱体+**双腕臂** (工作支+并行支, 沿线路错位) | 锚段关节柱2/柱3 |
| 中心柱 | 柱体+双腕臂 (两支同高平行) | 三跨关节中柱 |

- `ocs_support` 装配级配方按角色整棵重建; `ocs_cantilever` 叶片配方支持单腕臂细部编辑。
- 锚段布局 `AnchorMastLayout.Role` 自动标注 (端柱=锚柱, 其余=非锚柱/中间柱), 配方携带角色。
- **四跨锚段关节** `CreateOcsJoint`: 锚柱B-转换柱-转换柱-锚柱A + A/B 段接触线
  (柱2~柱3 并行, 非绝缘 200 / 绝缘 500) + 非工作支抬升下锚 (柱身回收 400mm);
  `OcsJointLayout` JSON 可存库编辑, `ocs_joint` 装配级 builder 确定性再生成。
- 验证: TestSupportRoles / TestAnchorVsNonAnchor (锚柱 X 向含拉线 > 非锚柱 3000+) /
  TestAnchorSectionRoleTagging / TestOcsJointAssembly (层级 21 元素 + 配方往返等价)。
- 视觉评审: 锚柱 (正视 45° 后置拉线+柱身补偿, 与非锚柱一目了然)、转换柱 (正视双腕臂
  前后错开)、四跨关节 (正视 4 柱+双支并行+下锚坡) 四视图全部通过。

## 四·六、转换柱几何修正 (2026-10 视觉评审回归)

首轮视觉评审发现转换柱两处几何错误, 已修复:

1. **双叉臂悬空** — 叉臂根部 (支架在 y=±300) 脱开柱身。修正为**横担+双叉臂**
   结构: 上下双横担 (沿线路贯通柱身, 跨长 2×(错位+250)) 承托两套叉臂根部,
   叶片 post + crossarm_upper/lower + cantilever_a/b (ocs_crossarm 叶片配方)。
2. **平腕臂"仰角"实际下垂** — `create_level_cantilever` 正角绕 +Y 使 +X 端向
   −Z 下垂, 而装配尺寸链 (定位管根部/承力索座/关节导线定位点) 全部按仰角向上
   假设定位 → 定位管悬空 174mm。修正旋转符号 (−angle, 与斜腕臂同约定),
   平腕臂真实上仰, 全链对位。
3. **关节导线与叉臂错位** — 叉臂沿线路错开 ±ArmYOffset 而导线折线点在柱位里程,
   导线不落在定位点上。修正: `OcsJointInput.ArmYOffset` (默认 300), A/B 段导线
   在转换柱处的定位点随叉臂同步错开 (TestOcsJointAssembly 断言对位)。
4. 连接性自动断言: TestTransitionMastConnectivity (横担覆盖双根部/上横担高度带
   包含叉臂顶/上下横担高差 1300)。
5. **下锚拉线与坠砣共面** — 原拉线横穿柱侧 (与下锚张力面成 90°), 违背下锚受力
   原理。新增 `mast_assembly_params.tensionPlaneY` (下锚张力平面, 跨距侧坠砣/
   下锚支所在): 补偿装置轮轴垂直折曲平面, 拉线自动布在张力平面对侧顺线路 45°
   平衡跨距张力。锚段端柱/关节锚柱按各自跨距朝向自动定边
   (TestAnchorGuyPlane 双向断言; 锚段 bbox 合法含两端外张拉线)。

## 四·七、GeoJSON 锚段入口与附加导线 (2026-10 追加)

- **线路方向驱动几何**: `CreateAnchorSectionFromGeoJSON(data)` 以线路中心线
  GeoJSON (Feature/LineString, 米) 生成锚段——支柱以各柱里程处法向朝向线路
  (曲线径向扇形布置, TestAnchorGeoJSONCurveDirection 断言 朝向⟂切向 且柱位距线
  CX), 腕臂/悬挂点/附加导线折线全部沿曲线; 整体布置 (导高/跨距/之字表/补偿/
  附加导线) 由 GeoJSON properties 参数化, 布局 JSON 仍是前端编辑面。
- **附加导线配置 (此前缺失, 已补)**: `AnchorSectionInput.AuxWires[]`
  (kind: AF正馈线/PW回流线/F加强线; offset 距线路中心 5m, height 8m, bracket
  支柱装横担式支架) → 布局折线 (支柱里程采样, 沿曲线) → 分段弛度放样
  (`ocs_aux_wire`) + 支架 (`ocs_aux_bracket`, CROSS_ARM 型)。
- 修复: 附加导线支架曾用壁挂板型 (板高=MountHeight → 双重偏移 15.8m; 且悬臂
  伸过导线 750mm 无连接, 视觉呈"错误平板"), 改为**水平管+斜撑**支架并真实对位到
  导线点 (按"距柱位最近采样"取导线点 — 密采样下索引不可假设); AF 线 ≤10m 密采样
  消除直弦折角; 承力索座对位到平腕臂端部 (原偏后 250mm);
  重建容器占位 vertex 移至子树几何中心 (原在原点, 曲线锚段重建 bbox 污染)。

## 四·八、锚段端部下锚引线 (2026-10 视觉评审回归)

锚段端柱处接触线/承力索原在叉臂悬挂点直接终止 (视觉"导线悬空断开")。
修正: 首跨/末跨跨距配方增加 `anchorDrop`+`dropDir`, 跨内生成**下锚引线**
(接触线/承力索自悬挂点沿指向柱身方向抬升 500mm 下锚至锚柱, 叶片
`anchor_drop_cw_0/mw_0` 等随跨距配方整棵重建)。跨距配方/装配级 builder/
往返测试同步覆盖。

## 四·九、参数化重建路径的支架板残留 (2026-10 视觉评审回归)

生成路径的附加导线支架已改管臂, 但**参数化重建路径** (`buildOcsAuxBracket`,
前端按配方重建时调用) 仍调用壁挂板图元 → 重建出的模型继续出现"十字板"。
修正: builder 与生成路径同构 (由配方 Position/Normal/OverhangLength/MountHeight
重建水平管+斜撑管臂)。教训: 同一构件存在"生成"与"重建"两条代码路径时,
改外观必须双侧同步 (本次以同构函数消除分歧)。

## 五、评审结论与遗留

**结论**: 组装层级已与铁路工程功能分解对齐, 前端可在 支柱装置/跨距/股道/道岔
粒度选择、编辑、重建; 零件级对象只在单元内展开, 满足"不在全局地图编辑金具"的目标。
参数化闭环在每一级成立 (叶片配方、跨距/股道装配配方、锚段/站场布局 JSON), 具备
"布局 → 单元 → 零件" 三级确定性重建能力。

**遗留建议** (按优先级):
1. **锚段关节/供电分段层**: 多锚段 + 关节 (绝缘/非绝缘转换) 尚无上级容器,
   建议后续增加 `ocs_network` (接触网网络 = 锚段列表 + 关节), 与站场级对偶。
2. **支柱装置子装配化**: mast 目前是 C++ 单复合体 (柱+腕臂融合), 若前端需要
   更换单个腕臂零件, 需把 create_mast_assembly 拆为 子装配 (柱/平臂/斜臂/绝缘子/
   定位管各自带配方), 层级再加一层。
3. **跨距与支柱的关联约束**: 跨距配方存的是两端悬挂点快照, 移动单柱后需重算
   邻跨 —— 现由布局层 (AnchorSectionLayout) 承担, 前端应编辑布局而非装配快照。
4. **道岔内零件分组**: turnout 仍为单复合体 (基本轨/尖轨/辙叉/岔枕), 与支柱装置
   同理, 若需岔内编辑可按 centerline_graph 方案拆子装配。
